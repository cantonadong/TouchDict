# TouchDict 设计规格

## 1. 目标

TouchDict 是面向 Windows 11、兼容 Windows 10 的轻量划词词典。用户在浏览器或其他桌面应用中选中一个英文单词，或在浏览器中选中多个英文单词后，通过触控板三指轻点唤出浮窗。浮窗依据选中文本及可获得的上下文，显示美式发音、上下文词性、中文释义、简单英文例句和例句中文翻译。

交付物是可直接运行的单文件 Windows EXE。程序应保持较低的常驻内存和 CPU 占用，不依赖本地服务器或数据库。

## 2. 用户流程

1. 用户启动 TouchDict，程序进入系统托盘并在后台等待。
2. 用户在任意应用中选中一个英文单词；浏览器中也允许选中英文短语。
3. 用户三指轻点触控板。Windows 触控板应将三指轻点映射为“鼠标中键”；程序也提供可配置的备用快捷键。
4. TouchDict 在不永久改变剪贴板内容的前提下读取选中文本，并尽量通过 Windows UI Automation 获取所在文本和上下文。
5. 浮窗立即在鼠标附近显示加载状态。
6. 程序调用 Gemini 免费层 API，要求返回结构化的词性、中文释义、英文例句和中文翻译。
7. 浮窗显示查询结果，并自动播放一次美式英语发音；用户可点击发音按钮再次播放。
8. 点击浮窗外部、按 Esc 或再次触发时关闭浮窗。托盘菜单可暂停监听、打开设置、打开预览和退出程序。

## 3. 触发与取词

### 3.1 三指触发

Windows Precision Touchpad 不向普通桌面程序公开独立的“三指轻点”应用级事件，因此采用系统映射：用户在 Windows 触控板设置中把三指轻点设置为“鼠标中键”。TouchDict 使用低级鼠标钩子监听中键事件。为兼容不能进行该映射的设备，程序提供全局备用快捷键，默认 `Ctrl+Alt+D`。

程序设置页明确显示配置说明和当前触发方式。触发监听不得吞掉普通中键事件；只有成功获得有效英文选区时才弹窗。

### 3.2 读取选区

取词分两级：

1. 优先使用 Windows UI Automation 的 TextPattern/TextPattern2 读取选区及邻近文本，不扰动前台应用。
2. 若目标应用不支持 UI Automation，则保存当前剪贴板内容，发送 `Ctrl+C`，等待目标应用写入文本，读取选区，然后尽力恢复原剪贴板。

仅接受包含拉丁字母的非空文本。非浏览器应用中的多词选区可查询，但界面提示其上下文识别可能有限。输入文本和上下文均设置长度上限，防止误选大段内容导致请求过大。

## 4. 查询服务

使用 Gemini REST API 的免费层。API 密钥从 EXE 同目录的 `gemini_key.txt`、用户设置或环境变量读取，优先级为用户设置、环境变量、同目录文件。密钥不得写入源码、日志或错误提示。

请求包含：选中文本、可用的上下文片段，以及严格的 JSON 输出要求。响应字段为：

- `term`：单词或选中文本；
- `partOfSpeech`：上下文中的词性，如 `adj.`、`n.`、`vt.`、`vi.`；
- `meaningZh`：当前上下文中的简明中文含义；
- `exampleEn`：对应含义的简单英文例句；
- `exampleZh`：例句中文翻译。

程序校验响应字段并限制长度。网络失败、限流、无效密钥、无有效内容和格式错误分别转换为用户可理解的状态，并允许重试。查询结果只在内存中做有界缓存，不建立用户词语历史数据库。

## 5. 美式发音

发音使用 Windows 自带语音合成接口，选择可用的 `en-US` voice，避免依赖收费或不稳定的第三方语音服务。若系统缺少美式语音，显示简短提示并保留查询结果。每次新查询成功后自动朗读一次；点击扬声器按钮可重复朗读。关闭浮窗时停止当前朗读。

## 6. 界面与交互

浮窗为紧凑圆角卡片，位于鼠标附近并自动避开屏幕边缘。内容从上到下为：

- 选中文本及发音按钮；
- 词性标签；
- 中文释义；
- 分隔线；
- 英文例句；
- 例句中文翻译；
- 必要时出现的错误、重试或上下文受限提示。

视觉风格使用浅色背景、深色正文、蓝色强调色和轻阴影；跟随系统缩放，确保高 DPI 屏幕清晰。状态覆盖 normal、loading、empty、error 和长文本 edge case。淡入和加载动效短促，不持续占用 CPU；系统关闭动画时应尊重该设置。

独立 Preview 入口复用正式浮窗组件和 mock data，可直接切换全部状态；它不依赖网络、密钥、权限或取词流程。正式业务逻辑只在同一 UI 组件确认可用后接入，避免预览与最终效果分叉。

## 7. 架构

采用 Go 和原生 Win32 API，生成单文件 GUI EXE：

- `cmd/touchdict`：应用入口、单实例、托盘和生命周期；
- `internal/trigger`：中键钩子和全局快捷键；
- `internal/selection`：UI Automation 与剪贴板回退；
- `internal/gemini`：Gemini REST 请求、结构化响应和错误映射；
- `internal/speech`：Windows SAPI 美式发音；
- `internal/popup`：原生浮窗绘制、状态和交互；
- `internal/settings`：本地配置、密钥来源和触发设置；
- `internal/preview`：mock data 和状态切换；
- `internal/logging`：不含敏感信息的轮转诊断日志。

模块通过小型接口通信。UI 只消费查询状态，不直接访问网络；取词模块不直接控制窗口；Gemini 模块不知道触发来源。

## 8. 数据与安全

- 仅在用户触发后读取当前选区，不监控键盘输入。
- 只把查询所需的选中文本和有限上下文发送给 Gemini。
- 不记录 API 密钥、完整请求正文、剪贴板内容或查询历史。
- 设置保存在当前用户的本地应用数据目录；密钥使用 Windows DPAPI 保护后保存。
- 日志只记录时间、模块、错误类别和非敏感诊断信息。

## 9. 错误处理

- 没有选区：不请求网络，显示短暂空状态或保持静默。
- 非英文选区：提示仅支持英文取词。
- 剪贴板被占用：短暂重试后提示无法读取选区，并确保不清空原剪贴板。
- API 密钥缺失：打开设置提示，不显示密钥内容。
- 网络不可用或超时：显示重试按钮；新获准联网后应完全退出并重启 EXE再测试。
- Gemini 限流或服务错误：显示服务繁忙并允许稍后重试。
- JSON 格式异常：执行一次受限修复解析，仍失败则显示响应异常。
- 语音不可用：查询结果仍正常显示，仅禁用发音按钮。

## 10. 构建与交付

构建目标为 Windows x64 GUI 单文件：

`D:\Dev\TouchDict\artifacts\TouchDict.exe`

用户要求不运行测试，因此开发阶段不执行测试套件。交付前只执行格式化、静态构建和生成 EXE，不启动程序验证网络或 UI。现有运行中的 `TouchDict.exe` 必须先完全终止，再覆盖同一路径。

同时维护 `docs/development-log.md`，记录阶段、环境、关键设计、已知限制和待用户验证项。

## 11. 验收标准

- Windows 11 上启动后常驻托盘，空闲时 CPU 占用接近零。
- 中键映射的三指轻点或备用快捷键可在选中英文后唤出浮窗。
- 能在常见浏览器和支持 UI Automation 的桌面应用中读取单词；剪贴板回退覆盖其他常见应用。
- Gemini 返回并展示词性、上下文中文义、简单例句和中文翻译。
- 新结果自动进行一次美式发音，按钮可再次播放。
- 所有 UI 状态可在 Preview 中查看。
- 缺少密钥、网络失败、无选区和语音不可用时不会崩溃。
- API 密钥不出现在源码和日志中。
- 最终交付一个固定路径、可直接运行的 EXE。
