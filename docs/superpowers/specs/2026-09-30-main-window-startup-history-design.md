# TouchDict 主窗口、共享历史与开机启动设计

## 目标

在保留现有托盘划词卡片的基础上，新增一个完整的桌面主窗口，使用户能够主动输入英文查询、浏览持久化查询历史，并从拼写错误候选词继续查询。主窗口与划词卡片必须使用同一查询服务和同一份最多 500 条的持久化结果集。

程序默认随当前 Windows 用户登录启动，但只驻留托盘。用户双击托盘图标或选择“打开主窗口”后才显示主窗口；关闭主窗口只隐藏窗口，不退出后台划词功能。

## 用户流程

### 主窗口查询

1. 用户双击托盘图标或选择“打开主窗口”。
2. 主窗口顶部显示查询输入框和“查询”按钮；按 Enter 与点击按钮行为相同。
3. 查询期间显示加载状态并阻止同一输入的重复提交。提交新查询时取消旧查询，旧响应不得覆盖新结果。
4. 查询成功后，右侧显示与查词卡片相同的数据：单词、词性、中文释义、英文例句、中文翻译和朗读操作。
5. 成功结果写入共享结果集，并立即更新左侧历史列表。

### 拼写建议

Gemini 的结构化结果支持两种互斥状态：有效词典释义或拼写候选。如果输入疑似拼错，例如 `goot`，界面显示“你可能想查”及若干可点击候选词，而不为错误输入编造释义。

点击候选词后，主窗口把候选词写回输入框并立即查询。只有成功取得有效释义的候选查询才进入共享结果集；只有候选而没有释义的原错误输入不进入历史。

### 共享历史

- 主窗口输入查询和划词卡片查询共用一份持久化结果集。
- 结果集最多保存 500 条，最新使用的记录在最前。
- 相同查询不创建重复记录，而是更新保存结果并移动到最前。
- 点击历史项直接显示已保存的结果、将其移动到最前，不重新请求 Gemini。
- 主窗口打开时，新的划词结果会同步刷新左侧历史。
- 旧版 `touchdict_cache.json` 必须可继续读取；缓存文件原地扩展，不新建重复的历史数据库。

缓存键继续以规范化查询文本与上下文构成，以便保留划词语境结果。历史项显示实际查询词；同一单词在不同上下文产生不同释义时允许分别保留。

## 主窗口界面

主窗口为可调整尺寸的普通桌面窗口：

- 顶部：查询输入框和“查询”按钮。
- 左侧：最近使用的查询历史，具有合理的固定最小宽度并支持滚动。
- 右侧：共享结果视图，覆盖空白、加载、释义成功、拼写候选和错误状态。
- 结果视图沿用查词卡片的字段、文案和朗读能力，但适应主窗口的可伸缩布局。

点击主窗口关闭按钮只隐藏窗口。托盘菜单增加“打开主窗口”，托盘图标双击执行相同行为。程序退出仍只通过托盘“退出”命令完成。

## 架构

### 共享查询协调层

从现有入口逻辑中抽出统一查询协调层。划词卡片与主窗口均向该层提交查询，由该层负责：

- 命中并更新共享缓存；
- 调用 Gemini；
- 管理取消与超时；
- 防止过期响应更新界面；
- 保存有效结果；
- 发布结果集变化通知；
- 向调用方返回加载、成功、候选或错误状态。

窗口不直接访问网络或缓存文件。浮窗继续负责鼠标附近的短暂交互，主窗口只负责桌面查询和历史浏览。

### 模块边界

- `internal/mainwindow`：主窗口布局、输入、历史选择、候选链接和结果显示。
- `internal/model`：扩展查询结果与视图状态，表示有效释义或拼写候选。
- `internal/gemini`：请求并校验扩展后的结构化响应。
- `internal/gemini/cache_windows.go`：提供最近记录快照、最近使用顺序更新、持久化及变更订阅能力。
- 新的共享查询协调层：连接 Gemini、缓存和两个 UI 入口。
- `internal/settings`：保存开机启动偏好并同步 Windows 当前用户启动项。
- `cmd/touchdict`：组装服务、窗口、托盘与生命周期，不承载查询业务规则。

## Gemini 响应

结构化响应应明确区分：

- `definition`：包含现有 `Definition` 的完整字段；
- `suggestions`：包含数量有限、去重且非空的候选词列表。

响应必须恰好提供一种有效状态。释义字段不完整、候选为空、两种状态同时无效或 JSON 无法解析时，按现有查询格式错误处理。候选词长度和数量必须受限，避免异常响应撑大界面或缓存。

## 开机自启动

设置窗口新增“开机自动启动”复选框，默认选中。配置字段需要支持迁移：旧配置中缺少该字段时按 `true` 处理。

保存设置时同步当前用户的 Windows 启动注册项，命令指向当前 EXE 的完整路径并正确引用含空格路径。该操作不要求管理员权限：

- 选中：创建或更新 TouchDict 启动项；
- 取消：删除 TouchDict 启动项；
- 同步失败：保留设置窗口并显示明确错误，不报告保存成功。

普通启动和开机启动行为一致：程序只进入托盘，不主动显示主窗口。

## 错误与并发

- 空白输入不发起查询，并在输入区域给出轻量提示。
- 网络不可用、超时、限流、无效密钥与响应格式错误显示在右侧结果区；可恢复错误允许重试。
- 主窗口的新查询取消其上一请求；划词卡片和主窗口可各自保持当前展示，但共享服务不得让旧响应覆盖同一入口的新状态。
- 缓存持久化失败记录非敏感诊断，并向主动查询入口显示可理解的错误；不得记录 API 密钥或完整请求正文。
- 主窗口关闭或隐藏时停止不必要的界面更新，但不终止托盘、触发监听或共享查询服务。

## 兼容与迁移

- Windows 11 x64 为主要目标，兼容 Windows 10 x64。
- 保持现有单文件 GUI EXE 架构与 Walk/Win32 技术栈。
- 继续读取现有设置和缓存；新字段缺失时使用安全默认值。
- API 密钥仍由 DPAPI、环境变量或 EXE 邻近文件提供，不写入日志或历史。
- 缓存上限保持 500，不建立第二份历史存储。

## 交付与验证

按用户规则不运行自动测试或手动启动测试。开发完成后仅执行：

- `gofmt` 格式化；
- Windows amd64 静态构建；
- 检查固定输出文件存在。

构建前终止所有正在运行的 `TouchDict.exe`，并覆盖同一路径：

`D:\Dev\TouchDict\artifacts\TouchDict.exe`

同时更新 README 和 `docs/development-log.md`，记录新入口、共享历史、开机启动和待用户验证项目。

## 验收标准

- 设置页显示默认选中的“开机自动启动”，保存后能正确创建或移除当前用户启动项。
- 登录启动只显示托盘，不弹出主窗口。
- 双击托盘图标和“打开主窗口”均能显示同一个主窗口实例。
- 输入查询后按 Enter 或点击按钮均能获得结果。
- 左侧历史最多 500 条，与划词卡片结果实时共用并在重启后保留。
- 点击历史项无需网络即可显示保存结果并更新最近使用顺序。
- 拼错输入显示可点击候选词；点击候选后查询对应内容。
- 右侧成功内容与现有查词卡片字段一致，网络和格式错误不会导致程序崩溃。
- 最终生成并覆盖固定路径的可运行 EXE，供用户测试。
